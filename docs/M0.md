# M0 implementation and operations

The deployment and backup configuration is implemented; the home server deployment, off-host copy and a real restore rehearsal remain operator tasks. M0 is not complete until those succeed and writing from browser and phone is verified.

## Deploy

Install Docker Compose and Tailscale on the host. Restrict access with Tailscale ACLs and host firewall rules; there is no application authentication. Set `PRIVATE_BIND_IP` to the host's Tailscale IPv4 address (never 0.0.0.0), `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, and `DATABASE_URL` in an untracked root `.env`. Use a long unique password and URL-encode credentials in `DATABASE_URL`, whose host is `postgres:5432`. Example shape: `postgres://USER:ENCODED_PASSWORD@postgres:5432/DB`. Then run `docker compose up -d --build`. Visit `http://TAILSCALE_IP:8080` from a tailnet device. Verify the bind and firewall independently. PostgreSQL and the API have no host ports.

## Backup and restore

Initialize a private git repository outside this checkout for exports and configure its git identity. Set `BACKUP_DIR`, `EXPORT_REPO`, and `OFFHOST_TARGET` (an rsync destination with SSH access) in the environment. Run `scripts/backup.sh` from the project root, and schedule it hourly with the same environment, working directory and Docker access. Monitor exit status and off-host availability. Dumps accumulate; configure retention according to your needs. Exports are sensitive plaintext; secure both destinations. Export filenames are document IDs, and deleted documents disappear from the current tree but remain in git history. Only saved documents are included.

To rehearse, copy a dump into an isolated test host or separate Compose project with its own volume and credentials. Start PostgreSQL, stop the API, then run `scripts/restore.sh /path/to/dump`. This replaces database objects; never run it on production without intending to overwrite data. Start the API and verify document contents and revisions. Test off-host retrieval, record the result, and repeat regularly. The dump is the authoritative backup; markdown exports contain current content only.

The toolbar counts net changes in whitespace-separated word counts made by typing or pasting during the current page session across documents. Deletions reduce the count to a minimum of zero; restoring history, loading, saving and discarding changes do not themselves change it. Reloading the page resets it. This is an approximate activity metric, not an audit of unique words.
